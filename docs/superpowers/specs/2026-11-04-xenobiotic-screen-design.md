# 外来の分子の走査（薬剤由来の特徴を見つける）設計

- 日付: 2026-11-04
- 関連: ms-data-parser `docs/superpowers/specs/2026-11-04-evidence-bundle-v3-samples-design.md`（根拠バンドル v3）、
  reanalysis-study `docs/specs/2026-11-04-xenobiotic-signals-design.md`（手順書での使い方）
- 状態: 実装済み。実データの較正は r3 で改訂後の条件に合格（§10.0）。手順書には入っていない

## 1. 目的と背景

公開データの再解析（reanalysis-study）で、薬剤の比較の run では、薬剤本体・その代謝物・イオン源の中の断片や付加体が
「処理群だけに出る特徴」になり、強い有意差として並ぶ。麻酔薬・溶媒・併用薬も同じように外から入る。今は、これを
系統的に見分ける道具が無い。実例:

- ST003841（メトホルミン）: 新しい知見の候補の上位に、ビグアニド類やトリアジンの組成の特徴（log2FC +8〜+21）が並んだ。
- ST002901（フルオキセチン）: 処理群だけに出る別物の名前の特徴（log2FC +13〜+17）と、麻酔薬ケタミンの代謝物の群差が出た。
- ST002755（アムロジピン、次の run）: 論文の L-proline（RT 14.14 分）は、アムロジピンが溶ける領域の薬剤由来のイオンの疑いがある。

本リポの索引にはこれらの薬剤の参照スペクトルがある（2026-11-04 に確認: アムロジピン 17、メトホルミン 41、ケタミン 20、
ノルケタミン 1、フルオキセチン 34 レコード。ファスジルは 0）。ただし既存の照合は「特徴の MS/MS → ライブラリ全体」の
向きで、薬剤本体なら候補に出るが、代謝物は合わない。**逆向き**、つまり「登録した外来の分子に関係する特徴を、データの中から
探す」道具を足す。

## 2. 目標・非目標・反目標

目標:

- 根拠バンドル（`load_evidence_bundle` で読んだ解析）の全特徴について、登録した外来の分子（薬剤・代謝物・溶媒・麻酔薬・
  併用薬）との関係を、**3 つの独立した筋**（質量・MS/MS の共有・出方）で示し、水準を付けて表に出す。
- 筋ごとの根拠（どの付加体・どの質量差・どの断片・何例で検出）を行に残し、水準だけを返さない。
- 参照スペクトルが索引に無い分子（ファスジルなど）も、組成式から質量と出方の筋で扱う。

非目標:

- 代謝物の in silico の予測（BioTransformer など）。登録された分子と固定の質量差の表だけを使う。
- 判定（再現したか）や総合評価を決めること。材料を出すだけで、使い方は reanalysis-study の手順書が決める。
- 外向きの通信。この走査はローカルの索引とバンドルだけで完結する（`resolve_pathways` の例外を増やさない）。

反目標（技術的に動いても失敗とみなす）:

- 質量差の組み合わせだけで、内因性の代謝物を薬剤由来と大量に印付けする（+O などの質量差は多くの物質に当たる）。
  単独の筋だけの一致は最も弱い水準に留め、判定に使える水準にしない。
- 特徴を黙って除く。走査は印を付けるだけで、特徴を消さない。
- 名前の文字列で推測する（化合物の名前は IUPAC 名が多く、名前は照合キーにしない。InChIKey と組成式だけを使う）。

## 3. 入力

### 3.1 登録（外来の分子の一覧）

新しいツール `register_xenobiotics(analysis_id, entries)`。`entries` は次の形の配列:

| 欄 | 必須 | 意味 |
|---|---|---|
| `entry_id` | ○ | 呼び出し側が付ける一意の ID（例 `X1`） |
| `role` | ○ | `drug` / `drug_metabolite` / `vehicle` / `anesthetic` / `co_medication` / `other` |
| `name` | ○ | 表示用の名前（照合には使わない） |
| `inchikey` | | 完全な InChIKey。索引の参照スペクトルを引く鍵。無ければ MS/MS の共有の筋は `unavailable` |
| `formula` | ○ | 中性分子の組成式（質量の筋の基）。InChIKey が索引にあっても必須（登録の側は索引を見られないので、いつも書かせる。設計者の判断） |
| `parent_entry_id` | | 代謝物なら親の `entry_id`（出方の筋で親と連動を見る） |
| `received_by` | ○ | `test` / `reference` / `both`（どちらの群に入ったか。溶媒・麻酔薬は `both`） |

`received_by` の `test` は、走査の呼び出しで渡す `test_group`（§6）の側を指す。登録は解析（`analysis_id`）ごとで、1 つの根拠バンドルは 1 つの比較
（manifest の `comparison` は 1 つ、`analysis_id` は manifest のハッシュ）なので、`received_by` は比較ごとに書ける。3 群以上の試験では比較ごとにバンドルを書き出し、
それぞれの `analysis_id` へ登録する（2026-11-13 の事実確認で「比較ごとに書けない」という指摘を確かめ、前提が誤りと分かった。§10.14）。戻り値は entry ごとに、索引のレコード数・極性・付加体、組成式と単一同位体質量、
警告（索引に無い、組成式と InChIKey の質量の食い違いなど）。登録は解析の成果物として保存し（既存の `artifacts/` の
仕組み）、再起動後も復元する。

### 3.2 根拠バンドル

既存の v2 に加え、**v3**（ms-data-parser の設計書）を読む。v3 は v2 に任意の 2 役割を足す:

- `samples`: `sample_id, group, role, injection_order`（`group` は `a` / `b` / 空）
- `intensities`: `feature_id, sample_id, value, detected`（`detected` は `true` / `false` / 空＝不明。補完した値は `false`）

v3 の読み込みでは `contract_version` 2 と 3 を受け、2 には `samples` / `intensities` が無いものとして扱う。今の
`experiment/bundle.py` は知らない役割を拒むので、`samples` / `intensities` を知っている役割に足す。v3 の manifest の
`comparison` には `polarity`（`positive` / `negative`）が入る。付加体の組はこれで選ぶ。v2 には無いので、v2 のバンドルでは
走査の引数 `polarity` を必須にする（設計者の判断）。契約の文書は
`docs/contracts/evidence-bundle-v3.md` に新しく書く（v2 の文書は残す）。features に任意の列 `adduct`（MS-DIAL の付加体の表記）
が付くことがある。

## 4. 3 つの筋

### 4.1 質量の筋

登録した分子ごとに、比較の極性の付加体の理論 m/z を作り、特徴の m/z と照らす（許容幅 `ppm` は呼び出し側が渡す。
再解析では工程 5 で決めた帯ごとの許容幅）。

- 付加体: 陽 `[M+H]+` `[M+Na]+` `[M+NH4]+` `[M+K]+` `[2M+H]+` `[M+2H]2+`、陰 `[M-H]-` `[M+Cl]-` `[M+HCOO]-` `[M+CH3COO]-` `[2M-H]-`。
- イオン源の中の損失: `-H2O` `-NH3` `-CO2`（付加体の後に 1 つまで）。「質量差を適用した組成 × 分子数 ＋ 付加体の add − remove」の組成に原子が足りるときだけ作る
  （酸素の無いメトホルミンに `-H2O` `-CO2` を付けない）。損失つきの一致は、それだけでは出方の筋と組んで水準 C の根拠にならない（§5）。
- 代謝の質量差（固定の表。表は版を付けてコードに置き、出力に版を書く）: 酸化 +O、二重酸化 +2O、脱メチル −CH2、脱エチル −C2H4、
  脱水素 −2H、水素化 +2H、加水分解 +H2O、グルクロン酸抱合 +C6H8O6、硫酸抱合 +SO3、グルタチオン抱合 +C10H15N3O6S、
  N-アセチル化 +C2H2O、メチル化 +CH2、グリシン抱合 +C2H3NO、タウリン抱合 +C2H5NO2S、脱塩素水酸化 −Cl+OH。
  組み合わせは 2 つまで（例: 脱メチル＋グルクロン酸抱合）。
- 特徴の `adduct` 列があれば、それと矛盾する付加体の一致を落とす。比べるのは損失を除いた付加体同士で（`[M+H-NH3]+` の付加体は `[M+H]+`）、特徴の `adduct` に損失が
  付いていれば同じく除く。落とした数は組ごとに `notes` の `adduct_conflict_dropped:<n>` に出す。
- ただし `adduct` が低得点の注釈の候補でしかない特徴（`source` が `msdial_sml` で名前が `low score:` で始まる注釈がある）は比べない。実測のイオンの判定ではないからである
  （r3 の前のユーザーの決定。§10.9 の 13981）。`notes` に `adduct_low_score`、要約の `counts` に `adduct_low_score_ignored` を出す。`msdial_sml` の注釈が無い特徴の `adduct` は既定の値のことがあるが、従来どおり比べる。

行に残すもの: 一致した entry、付加体・損失・質量差の名前、理論 m/z、ppm。同じ特徴に複数の一致があれば全部残す
（質量差の数が少ない方を先に並べる）。

### 4.2 MS/MS の共有の筋

登録した分子の索引の参照スペクトル（同じ InChIKey の全レコード）から、product ion と neutral loss のビンの和集合を作り、
ビンごとに背景の IDF（`axis_background`）で重みを付ける。特徴の MS/MS（バンドルの spectrum_links で結ばれたもの）の
ビンと照らし、

- 共有の得点 = 共有したビンの IDF の和 ÷ 参照の上位ビン（相対強度の上位 N 本）の IDF の和
- 共有したビンの数、共有した断片の組成式（索引に `formula` があれば。塩素などを含む断片は特に意味が大きい）

を行に残す。代謝物は修飾の位置を含まない断片か、修飾を含む側の中性損失を共有するので、product ion と neutral loss の
両方を数える。前駆体の質量差だけずらした断片の照合（シフトした断片）は第 2 段階に回す（§9）。

あわせて、既存の順向きの照合（`match_feature_spectra` と同じエンジン）で、登録した分子そのものが候補の何位に出るかを
`forward_rank` として残し、その候補の `band` を `notes` の `forward_band:<band>` に残す。順位だけでは同定の根拠にならない（§5）。

参照スペクトルが索引に無い分子は、この筋が `unavailable`。

### 4.3 出方の筋

バンドル v3 の `samples` / `intensities` を使う。無ければ `unavailable`。

- **群の偏り**: `received_by` が `test` の分子に関係する特徴は、検出（`detected` が真）の例数が test 群で多く reference 群で
  ほぼ無い形か。既定は「test で過半数、reference で 1 例以下」。`both` の分子は群の偏りを見ない（二次的な交絡の扱い。§5）。
- **親との連動**: 代謝物の一致で、親の entry に水準 A の特徴があるとき、test 群の試料の中で親の
  特徴の値との Spearman の ρ。既定は n ≥ 5 で ρ ≥ 0.6 を連動とする。代謝物の一致とは、`parent_entry_id` のある entry の一致（質量差の有無を問わない。
  登録済みの代謝物そのものも代謝物の一致である）と、`parent_entry_id` の無い entry の質量差つきの一致（親はその entry 自身）を指す。

## 5. 水準

特徴と entry の組ごとに 1 つの水準を付け、特徴の水準は組の中で最も強いもの。

| 水準 | 条件 | 再解析での使い方（参考。決めるのは手順書） |
|---|---|---|
| **A 本体** | 質量の筋で entry 本体（質量差なし）の付加体か損失に一致し、`forward_rank` が 1 で、その候補の `band` が `PASS` | 判定・総合評価に使う |
| **B 強い** | 質量の筋の一致（質量差 2 つまで）があり、MS/MS の共有の得点が閾値以上。質量差のある一致だけの組は、親との共起も要る（下の改訂） | 判定・総合評価に使う |
| **C 示唆** | 質量の筋か MS/MS の共有の筋のどちらか 1 つがあり、出方の筋が成り立つ。質量の一致が損失つきだけなら、親との連動があるときに限る | 新しい知見の候補の印 |
| **D 弱い** | 1 つの筋だけ | 一覧に載せるだけ |
| なし | どの筋も無い | — |

`both` の分子（溶媒・麻酔薬など）は出方の筋の群の偏りを使わないので、C は「質量か MS/MS の共有 ＋ 親との連動」のときだけ。

**A の定義の改訂（2026-11-05、最終レビュー）。** 初版の A の条件は「質量の本体の一致 かつ `forward_rank` が 1」で、`band` を見なかった。順向きの照合は
`(-weighted_score, accession)` で並ぶので、全候補が得点 0 のとき順位 1 は accession の文字列順で決まり、断片が 1 本も合わなくても A が付いた（実測で §10.6 の 1）。
これは単独の筋を判定に使わせない §2 の反目標と、`PRECURSOR_ONLY` を `PASS` と同一視しない CLAUDE.md の規約に反する。上位の反目標を優先して `band` が `PASS` の条件を足した。
A が減り、親の水準 A の特徴を使う連動も同じ分だけ減る。

**C の定義の改訂（2026-11-05、r3 の前。ユーザーの決定）。** 損失つきの質量の一致（例: `[M-H-NH3]-`、`demethylation|[M-H-NH3]-`）は、MS/MS の共有（`msms_shared_min` 以上）か親との連動があるときだけ C の根拠にする。
§10.10 のとおり、r2 でおとりの C を増やしたのは損失つきの一致だけで付いた組だった。損失の無い一致が 1 つでもある組の扱いは変えない。損失つきの一致に MS/MS の共有があれば、従来どおり B の条件を満たすので結果は B になる（C より強い）。だから C の分岐で効くのは親との連動だけである。B の条件は変えていない。

**B の定義の改訂（2026-11-05、r4 の後。ユーザーの決定「案 1」）。** 質量差のある一致だけの組（entry 本体と同じ組成の一致が無い組）は、MS/MS の共有があっても、**親との共起**が成り立つときだけ B にする。成り立たなければ B にせず、C・D の判定に回す。
- **親の特徴**: その entry と、`parent_entry_id` をたどった先祖の entry のどれかに、質量差なし・損失なしで一致する特徴（自分を除く）。水準は問わない。代謝物は本体を受けた個体にしか出ないので、本体の質量の信号が同じ試料にあるかを見る。本体の MS/MS が取られていない run（MTBLS3233 のアムロジピン本体 14386 など）でも働くよう、A に限らない。
- **共起**: その特徴が検出（`detected` が真）された試料（比較の両群）のうち、親の特徴のどれかも検出された試料の割合が `codetect_min_fraction`（0.5）を**超える**とき成り立つ。検出が 1 例も無い、または検出が分からない（出方の筋が使えない）ときは成り立たない（厳しい側）。
- **理由。** r4（§10.11.1）の B の偽陽性 4 件は、段数（1〜2）・付加体（損失の有無）・共有の得点（0.126〜0.186）のどれでも全部を分けられず、共通点は「その個体に親がいない」ことだけだった。r4 の結果を見て作った規則なので、r5（§10.12）で、まだ使っていない run で確かめる。
- **失うもの。** 本体がほとんど残らない薬（全量が代謝される）では、代謝物が B に届かなくなる。質量差なしの一致（登録した代謝物そのもの、例: ノルケタミン）には効かない。
- 要約の閾値に `codetect_min_fraction` を足し、閾値の版を `xeno-thresholds-2026-11-05-r5` にした（MS/MS の閾値の値は r3 のまま）。共起の数は行の `notes` に `parent_codetected:k/n` として書く。

閾値（MS/MS の共有の得点、上位 N、出方の既定値）は §8 の較正で決め、決めた値と版を出力に書く。

## 6. 出力

新しいツール `screen_xenobiotic_features(analysis_id, test_group, ppm, ppm_bands=None, polarity=None, max_shifts=2, output_path=None, ppm_offset=None, coelution_rt_tol=0.1)`。

- `test_group` は、バンドルの `comparison` の `group_a` か `group_b` の名前（薬剤を受けた側）。どちらとも一致しなければ誤りで止める。
  出方の筋の群の偏りと、表の `detected_test` / `detected_reference` はこれで決まる。名前から推測しない。
- `polarity` は v3 では manifest から読み、引数と食い違えば誤りで止める。
- `ppm_offset`（2026-11-16 に追加）は質量の窓の中心のずれ。形は ms-data-parser の `ppm_offset` と同じ `{"default": 0.0, "bands": [{"max_mz", "offset"}]}` で、
  上流の工程 5 で決めた値をそのまま渡せる。中心は「実測 − 理論」の ppm、帯は理論 m/z が `max_mz` 未満の最初の帯（無ければ `default`）。窓は
  理論 m/z × (1 + (中心 ± 許容幅) ppm) になる。幅と行の `ppm` 列（実測 − 理論）は変わらない。渡したときだけ要約の `params.ppm_offset` に残す（渡さなければ記録は前と同じ）。
  §10 の較正と検証はどれも `ppm_offset` なしで走らせた。
- `coelution_rt_tol`（2026-11-16 に追加、分）は共溶出の印の RT の幅。下の `coeluting` 列を決めるだけで、水準には使わない。

- 戻り値は要約だけ: 水準ごとの特徴の数、有意な特徴（バンドルの `significant`）のうち水準ごとの数、entry ごとの水準 A・B の数、
  筋ごとの `unavailable` の理由、質量差の表と閾値の版、索引の識別（`index` の `bin_width`・`built_at`）、`intensities_stage`、較正の合否（`calibration`）。
  バンドルの `spectrum_links` が空で、manifest の `provenance.spectrum_links_status` が `verified_alignment` でなければ（`not_provided`・`id_space_mismatch`・`id_space_unverified`・記載なし）、
  MS/MS の筋全体が `unavailable` である。`unavailable.msms_all` を `no_spectrum_links` にし、状態を `unavailable.spectrum_links_status` に載せ、各行の `notes` は `no_msms` でなく `msms_unavailable:no_spectrum_links` とする
  （MS/MS の有無が分からないので全特徴を `no_msms` と言わない。A・B が 0 を「薬剤由来なし」に読ませない）。`n_features_without_msms` は `null`。`verified_alignment` で空なら、対応づけた結果 MS/MS が無かったので従来どおり `no_msms`。
- 全行は TSV で `output_path`（省略時は成果物の置き場所）に書く。列:
  `feature_id, mz, rt, log2fc, q_value, significant, level, entry_id, role, relation, theoretical_mz, ppm,
  msms_shared_score, msms_shared_n, msms_shared_formulas, forward_rank, detected_test, detected_reference, rho_parent, notes, coeluting`。
  1 つの特徴に複数の entry の一致があれば行を分ける。
- **共溶出の印 `coeluting`（2026-11-16 に追加。ユーザーの決定「印だけ足す」）。** 行の一致と同じ分子（同じ entry・同じ質量差の組）の、別のイオンの形

### 10.6 較正で見つかった問題

r1 で見つけ、1 と 2 は最終レビューの修正で直した（§5・§4.1）。3 は意図どおりで直していない。数は r1 のもの。

1. **水準 A が精密質量だけで付く（直した）。** `forward_rank` は `PRECURSOR_ONLY` の候補も順位に数えるので、断片が 1 本も合っていなくても前駆体の質量が合えば 1 位になる。
   PASS でない A は ST003841 で 4/6（4349・4351・4355・4368）、ST002901 で 2/53（13249・13250）。13250 は対照群でも 6 例検出され、RT も別で、ノルフルオキセチンではないとみられる。
   ノルフルオキセチン 13249 の「満たした」もこの経路で、MS/MS の裏付けは無い（出方 8/0 と質量だけ）。おとりの A が 0 なのは、登録した分子の `[M+H]+` の質量に特徴が無かったためで（本体の一致は陽イオンの `[M+NH4]+`・`[M+2H-CO2]2+` の 3 件だけ）、
   A の厳しさを示していない。`band` が `PASS` の候補に限る修正の結果、13249 は C に下がり、期待の B を満たさなくなった（§10.7）。
2. **付加体の矛盾の除去が、イオン源の中の損失を落とす（直した）。** MS-DIAL の `adduct` は同定の候補のイオンで、実測のイオンの判定ではない。文字列の完全一致で比べるので、
   `[M+H]1+` と書かれた特徴から `[M+H-NH3]+` の一致が消える（ST003841 の 3156 はメトホルミンの −NH3 の組成なのに質量の筋が無く、MS/MS の共有だけで C に届いた）。
   落とした一致は ST003841 で 1,702、ST002901 の陽イオンで 6,164。直した後は 1,026・4,558。この修正がおとりの C を増やした（§10.0）。
3. **`detected` の例数が少ない特徴は出方の筋に乗らない。** 群の平均では処理群だけに見えても（log2FC +13〜+15）、実測の検出は 1〜2 例のことがある。平均の差は補完の値の差に
   由来する（6126 は 2/5 例、9187 は 1/8 例）。これは出方の筋が意図どおり働いた結果で、レポートの推定の方が弱かった可能性がある。

### 10.8 実装で決めたこと

計画の「設計との食い違い・設計の補足」:

- **artifacts の仕組み**（§3.1）: 既存の `EvidenceStore`（`artifacts/evidence.sqlite` の `snapshots` / `heads`）。登録は種別 `xenobiotics`、走査は種別 `xenobiotic_screen` のスナップショット。解析の根拠版が変わるので `get_comparison_evidence` の古いカーソルは `stale_cursor` になる。
  根拠版は全種別の `heads` から作るので、版を引用した主張も古くなる: 登録か走査の前の `evidence_revision` を持つ主張は、`validate_comparison_claims` で `evidence_revision_mismatch` になる。登録か走査の後は、根拠を引き直して版を取り直す。
- **v3 の試料の値の置き場所**: `EvidenceBundle` に足さず、ストアの `sources` 表の複製から読み直す（`EvidenceStore.read_source`）。`Feature` には任意の `adduct` を足した。
- **`intensities_stage` の位置**: manifest の最上位キー。ms-data-parser の見本も同じ。
- **v3 の厳しさ**: `samples` と `intensities` は両方そろえるか両方省く。v2 に書けば誤り。`group` の数は `n_a` / `n_b` と一致し、`intensities` は全特徴 × `group` が a/b の全試料をちょうど 1 回ずつ持つ。
- **`ppm_bands` の形**: `[{"min_mz": float|null, "max_mz": float|null, "ppm": float}]`、半開区間 `[min_mz, max_mz)`、理論 m/z で帯を選ぶ。重なりは誤り。どの帯にも入らなければ `ppm`。
- **`relation` の書式**: `<質量差>|<イオン>`。質量差が無ければ `parent`、あれば表の順に `,` で連結。損失はイオンの `]` の前に入れる。MS/MS の共有だけの行は `msms_only`。
- **同じ m/z になるイオンの形**: 理論 m/z が 1e-6 Da 未満で一致する形は最も単純なもの 1 つに畳む。化学的に不自然な一致は残るが、質量の筋だけでは D に留まる。
- **1 つの (特徴, entry) に複数の質量の一致**: 一致ごとに行を分け（質量差の数 → |ppm| の順）、`level` 以下の組の値は各行に繰り返す。
- **共有の得点**: 分母は参照の上位ビン（product ion と neutral loss それぞれ相対強度の上位 `msms_top_n` 本）の IDF の和、分子は共有したビンのうち上位ビンに入るものの IDF の和。`msms_shared_n` と `msms_shared_formulas` は和集合全体で数える。
- **前駆体の残り**: 参照とクエリの両方で、前駆体 − 0.5 以上の product ion は共有に数えない。
- **一対一**: ±1 ビンを探り、中心ビンを優先して参照のビンを一度だけ使う（`spectral/matcher.py` と同じ規則を `xenobiotic/msms.py` に書いた）。
- **`forward_rank`**: `match_spectrum_result(conn, spectrum, 'LC-ESI-MS2', DEFAULT_PRECURSOR_TOLERANCE, top_k=20)` の候補を重複を除いた InChIKey の順に並べたときの順位（1 始まり）。複数のスペクトルなら最小、同順位なら `band` の強い方。上位 20 に無ければ空。`band` は、その InChIKey の先頭の候補（順位を決めた候補）のもので、同じ InChIKey の別のレコードの `band` は見ない。
- **水準 D**: 「1 つの筋だけ」は質量か MS/MS の共有のどちらか 1 つ。出方だけの組は行にしない。
- **親との連動の「親」**: `parent_entry_id` があればその entry、無く質量の一致が質量差つきなら entry 自身。親の水準 A の特徴が複数あれば ρ が最大のものを取り、`notes` に `parent_feature:<id>`。ρ は test 群の試料のうち、両方の値があり、どちらの `detected` も `false` でない試料で計算する。
- **索引に参照スペクトルの無い代謝物**: 自身の entry の組は最高 C。B には親の entry の組（質量差 2 つ）と親の参照スペクトルの共有で届く。
- **合格の条件が届かないかもしれない点**: フルオキセチン・ノルフルオキセチンの索引は全部陽イオン。陰イオンの 2 件は §8 のとおり条件から外した。
- **索引を開けないとき**: 登録も走査も `missing_index` で止める。

統括の決定:

- R1: `EvidenceStore.head_revision(analysis_id, kind)` を足し、`get_snapshot` と組で読む（カーソルの版を取るため）。
- R2: `tests/test_evidence_stdio.py` のツール数を 15 から 18 に直した。
- R3: 特徴の adduct は比べる前に MS-DIAL の表記 `]1+` `]1-` を `]+` `]-` に正規化する。
- R4: 親の水準 A の特徴の候補から、その組の特徴自身を除く（同じ特徴との ρ は常に 1 で、`both` の entry に偽の C が付く）。
- R5: `parse_intensities` は `group` が空の試料の行を `BundleError` にする。
- R6: 親との連動は `parent_entry_id` のある entry では質量差なしの一致にも適用する。
- R7: `SHIFTS` の表は `demethylation` を先頭に動かした（`relation` の順の例と合わせるため）。
- R8: 負の元素数の判定は質量差を 1 つずつ適用し、途中でも負なら作らない。
- R9: `detected` が全部空のとき親との連動も止める（出方の筋全体が `unavailable`）。
- R10（覆した）: 水準の無い特徴の行も `detected_test` / `detected_reference` に値を入れ、それ以外の `entry_id` 以降を空にする。検出の例数は特徴の値で entry に依らず、§6 の全行の列で、
  処理群だけの未知の特徴を TSV で探すのは §1 の目的に要るため（当初の「`detected_*` も空にする」は計画の字義で、spec を優先した）。`detection_unknown` のときは空のまま。
- R14: 水準 A に `band` が `PASS` の条件を足した（§5 の改訂）。
- R15: 付加体の矛盾は損失を除いた付加体同士で比べる（§4.1）。組ごとに落とした数を `notes` に出す。水準の無い特徴の行には entry を問わず合計を出す。別の entry の行だけがある特徴では、行の無い entry の分は行に出ず、要約の `counts` にだけ入る。
- R16: 損失は組成に足りるときだけ作る（§4.1）。付加体の表の版は `xeno-adducts-2`。`[M+HCOO-H2O]-` のように付加体が持ち込む原子も足りる側に数える。
- R17: 閾値の選び方を改めた（§10.10）。おとりの条件を満たす点が無く、規則では選べなかった。
- R18: M3・M4・M5 と Task 1〜6・8 の繰り越しは直さない。
